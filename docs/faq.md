# 常见问题

| 现象 | 处理 |
|---|---|
| 连接失败 | 确认 `api_v2.py` 已启动、端口正确；`/tts_status` 只能说明接口可达，不代表模型可用 |
| 提示“接口地址配置无效” | 地址必须是 `http://` 或 `https://`，不能带账号密码、查询参数或 `#` |
| HTTP 400 / 422 | 检查服务端路径、参考文本、语言和模型版本，详细原因见 GPT-SoVITS 控制台 |
| 返回 HTML 或 JSON 而不是音频 | 端口接错（如 Gradio 的 9874）、反向代理错误页或旧版 `api.py` |
| 合成超时 | 缩短文本或提高 `api.timeout`（最大 240 秒）；CPU 推理较慢 |
| 提示“正在合成其他语音或执行设置任务” | 插件同时只处理一个任务，请稍后重试 |
| 第二步底模版本显示“自定义权重” | 所选文件不是本机已安装的标准底模、版本无法识别，或该版本的标准底模没有安装；仍可合成，但不能使用 LoRA |
| 第二步状态为红色“版本不一致” | 已保存的版本与按文件识别的结果不同，重新点击“保存底模并继续”即可 |
| 语音已合成但发送失败 | 检查适配器是否支持 voice/WAV |
| 多情感时情感总是默认情感 | 第三步确认已勾选 2 个以上情感并读取角色配置、开启了 LLM 判断；用“试判断”检查所选模型任务是否可用；失败原因会显示在“当前配置检查”里 |
| 角色列表为空 | 把角色文件夹放到 GPT-SoVITS 安装目录下的 `maibot_roles` 后刷新；每个角色文件夹里要有 `role.json`（`maibot_roles/<角色>/role.json`），不能直接放在 `maibot_roles` 根目录；“当前配置检查”和角色列表下方会列出每个文件夹的问题 |
| 读取角色提示底模不在 GPT-SoVITS 中 | 按提示把 `base_model` 文件复制到给出的 `GPT_SoVITS/pretrained_models/...` 路径（角色文件夹里的副本不会被使用），或从 Hugging Face 下载，见 [部署 GPT-SoVITS](gpt-sovits.md) 中的“底模选择与下载” |
| 普通模式参考音频下拉框为空 | 把参考音频放到 GPT-SoVITS 安装目录下的 `maibot_refs`（文件夹不存在就新建），在第三步点“刷新参考音频” |
| LoRA 没有选项 | 需要 `.pth` 格式的 LoRA 文件；GPT 的 `.ckpt` 不是 LoRA |
| 原生配置页下拉为空 | 保存模型目录后点“刷新模型列表”，再重新进入配置页 |
| 更新后行为没变化 | 在 MaiBot 中重载插件或重启；只刷新浏览器不会更新已加载的代码 |
